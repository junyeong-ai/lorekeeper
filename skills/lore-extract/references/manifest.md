# Extraction manifest

The manifest lives in the vault (not the project repo), and the directory names the project —
it is the address every reader keys off, so nothing inside the file repeats it:

```
<vault>/.lorekeeper/extracts/<project>/manifest.yaml
```

Generated by scan, consumed by run, verified by audit. Editable
by the user between phases for overrides.

**Schema:**

```yaml
project:
  repo_path: <absolute-path>
  last_scan: <ISO-date>
  git_head_at_scan: <short-sha>   # null when the repo is not under git — staleness then reads "not measured"

discovered_sources:
  - path: "docs/adr/*.md"
    kind: adr           # adr | learning | rule | guide | spec | module-doc | other
    count: <discovered>
    transferability_default: T1

domains:
  <domain-name>: [<tag>, <tag>, ...]

strip_patterns:          # project identifiers to generalise away
  - "my-project-prd"
  - "my-project-dev"

concept_mapping:         # project tag → vault category id
  gcp: cloud-platform
  oauth: auth-identity

extracted:               # per-document tracking (written by run)
  - source: "docs/adr/some-adr.md"
    vault_page: "<wiki>/documents/proj-some-adr.md"  # vault-relative; <wiki> is the configured wiki dir
    domain: cloud-platform
    extracted_at: <ISO-date>
    extracted_at_commit: <short-sha>   # what THIS page was written from; null without git
    transferability: T1
  - source: "README.md"     # a T4 skip is recorded too, so audit coverage is complete
    vault_page: null
    transferability: T4
    coverage_note: "Skipped — project-specific, no transferable knowledge."
```

One source can feed several documents and several sources can fold into
one (theme-driven extraction, not 1:1). When several fold into one, record
`extracted[].source` as a LIST of the verbatim source paths (each still
filesystem-checkable for re-scan diffing) plus a `coverage_note` — never a
synthetic label like `"a + b"`, which would look deleted on the next scan.

## Source retention

Reuse a verified capture of the same repository and revision. Retain the source
files and dependencies actually read, with their paths, revision and byte digests;
a commit URL alone does not preserve bytes. Published citations must not point at
temporary checkouts. A summary does not replace the source evidence.

The extraction manifest records coverage, not every evidence dependency. Advancing
the scan, superseding a page or finishing extraction does not release an older
capture: published pages, retained review archives and unfinished queue/work inputs
may still cite it. Remove retained evidence only after those consumers have been
checked and any replacement has been verified at the published addresses.

Regenerable indexes and checkout caches have a different lifetime. Reclaim them
through their owner's locking protocol when no longer needed; preserve source
bytes, Git objects needed to reconstruct the recorded revision, and manifests.
`lore maintenance` prunes owned operational history, proven published work caches
and expired document projections, reclaiming empty projection namespaces and inactive
claims. Its dry run previews eligible projection payloads without creating cache files
or renewing their lifetime. It does not own ad-hoc repository copies under
`source-snapshots/`.
